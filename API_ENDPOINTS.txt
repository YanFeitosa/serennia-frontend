API da Serenna - Endpoints Propostos

Visão geral:
- API REST pensada para integrar o front atual.
- IDs são strings (UUID ou similares).
- Datas são strings ISO 8601.

1) Autenticação e sessão

Endpoint: POST /auth/login
Função: Autenticar usuário por e-mail e senha.
Entrada:
  email: string
  password: string
Saída:
  user: User
  accessToken: string
  refreshToken?: string

Endpoint: POST /auth/logout
Função: Invalidar a sessão/token atual.
Entrada:
  Header Authorization: Bearer <token>
Saída:
  HTTP 204 (sem corpo)

Endpoint: POST /auth/refresh
Função: Renovar o accessToken a partir de um refreshToken.
Entrada:
  refreshToken: string
Saída:
  accessToken: string

Endpoint: GET /auth/me
Função: Retornar dados do usuário logado (usado para Sidebar, controle de permissões, etc.).
Saída:
  User


2) Usuários e Colaboradores

Endpoint: GET /users/me
Função: Alias de /auth/me, para garantir um ponto único de leitura do usuário logado.
Saída:
  User

Endpoint: GET /collaborators
Função: Listar colaboradores (tela de Colaboradores, agenda, comissões).
Query opcional:
  status: 'active' | 'inactive'
  role: UserRole
  search: string (nome/email)
Saída:
  Lista de Collaborator

Endpoint: GET /collaborators/:id
Função: Detalhes de um colaborador (perfil, eventualmente com métricas de faturamento/comissão).
Saída:
  Collaborator
  (opcional) métricas agregadas

Endpoint: POST /collaborators
Função: Criar colaborador.
Entrada:
  Campos de Collaborator, exceto id, createdAt, updatedAt
Saída:
  Collaborator criado

Endpoint: PUT /collaborators/:id
Função: Atualizar dados do colaborador (nome, role, status, commissionRate, etc.).
Saída:
  Collaborator atualizado

Endpoint: PATCH /collaborators/:id/status
Função: Ativar ou inativar colaborador rapidamente.
Entrada:
  status: 'active' | 'inactive'


3) Clientes

Endpoint: GET /clients
Função: Listar clientes (tela de Clientes).
Query opcional:
  search: string (nome/telefone/email)
  tag: string
  page: number
  pageSize: number
Saída:
  Lista paginada de Client

Endpoint: GET /clients/:id
Função: Detalhes de um cliente (perfil do cliente).
Saída:
  client: Client
  (opcional) lastOrders: Lista de Order para timeline do perfil

Endpoint: POST /clients
Função: Criar cliente (tela de novo cliente / fluxo vindo de comanda ou agenda).
Entrada:
  Campos de Client, exceto id, createdAt, updatedAt
Saída:
  Client criado

Endpoint: PUT /clients/:id
Função: Atualizar dados do cliente.
Saída:
  Client atualizado

Endpoint: GET /clients/:id/orders
Função: Listar comandas associadas a um cliente (histórico no perfil).
Saída:
  Lista de Order


4) Catálogo - Serviços

Endpoint: GET /services
Função: Listar serviços (tela de Serviços, seleção na agenda, totem).
Query opcional:
  search: string
  category: string
  isActive: boolean
Saída:
  Lista de Service

Endpoint: GET /services/:id
Função: Detalhar um serviço para edição.
Saída:
  Service

Endpoint: POST /services
Função: Criar serviço.
Entrada:
  Campos de Service, exceto id, createdAt, updatedAt
Saída:
  Service criado

Endpoint: PUT /services/:id
Função: Atualizar serviço (nome, duração, preço, comissão, etc.).
Saída:
  Service atualizado

Endpoint: PATCH /services/:id/status
Função: Ativar ou inativar serviço (isActive).
Entrada:
  isActive: boolean


5) Catálogo - Produtos

Endpoint: GET /products
Função: Listar produtos (tela de Produtos, seleção na comanda).
Query opcional:
  search: string
  category: string
  isActive: boolean
Saída:
  Lista de Product

Endpoint: GET /products/:id
Função: Detalhar produto.
Saída:
  Product

Endpoint: POST /products
Função: Criar produto.
Entrada:
  Campos de Product, exceto id, createdAt, updatedAt
Saída:
  Product criado

Endpoint: PUT /products/:id
Função: Atualizar produto (nome, preço, estoque, etc.).
Saída:
  Product atualizado

Endpoint: PATCH /products/:id/status
Função: Ativar ou inativar produto.
Entrada:
  isActive: boolean


6) Agenda (Appointments)

Endpoint: GET /appointments
Função: Listar agendamentos para a agenda principal.
Query:
  from: string (data inicial)
  to: string (data final)
  collaboratorId?: string
  status?: AppointmentStatus
Saída:
  Lista de Appointment

Endpoint: GET /appointments/:id
Função: Obter detalhes de um agendamento (edição).
Saída:
  Appointment

Endpoint: POST /appointments
Função: Criar agendamento.
Entrada:
  clientId: string
  collaboratorId: string
  serviceIds: string[]
  start: string (ISO)
  end: string (ISO)
  origin: AppointmentOrigin
  notes?: string
Saída:
  Appointment criado

Endpoint: PUT /appointments/:id
Função: Atualizar agendamento (reagendar, trocar profissional, alterar serviços, etc.).
Saída:
  Appointment atualizado

Endpoint: PATCH /appointments/:id/status
Função: Atualizar status do agendamento.
Entrada:
  status: AppointmentStatus


7) Comandas (Orders)

Endpoint: GET /orders
Função: Listar comandas (tela de Comandas, filtros e busca).
Query opcional:
  status?: 'open' | 'closed' | 'paid'
  clientId?: string
  search?: string (nome do cliente ou id da comanda)
  from?: string
  to?: string
Saída:
  Lista de Order

Endpoint: GET /orders/:id
Função: Detalhes de uma comanda (itens, valores, cliente).
Saída:
  Order
  (opcional) client: Client

Endpoint: POST /orders
Função: Abrir nova comanda para um cliente.
Entrada:
  clientId: string
  appointmentId?: string
Saída:
  Order criada

Endpoint: PATCH /orders/:id
Função: Atualizar metadados da comanda (status, discount, etc.).
Entrada:
  Campos parciais de Order, principalmente status e discount
Saída:
  Order atualizada

Endpoint: POST /orders/:id/items
Função: Adicionar item (serviço ou produto) a uma comanda.
Entrada:
  type: 'service' | 'product'
  serviceId?: string
  productId?: string
  collaboratorId?: string
  quantity?: number
Saída:
  Order atualizada

Endpoint: DELETE /orders/:id/items/:itemId
Função: Remover item da comanda.
Saída:
  Order atualizada

Endpoint: POST /orders/:id/close
Função: Fechar comanda (status passa para 'closed').
Saída:
  Order atualizada

Endpoint: POST /orders/:id/reopen
Função: Reabrir comanda fechada, se a regra de negócio permitir.
Saída:
  Order atualizada


8) Pagamentos

Endpoint: GET /orders/:id/payments
Função: Listar pagamentos relacionados a uma comanda.
Saída:
  Lista de Payment

Endpoint: POST /orders/:id/payments
Função: Registrar pagamento de uma comanda (tela de PagamentoComanda).
Entrada:
  method: PaymentMethod
  amount: number
Saída:
  order: Order
  payment: Payment

Endpoint: POST /payments/:id/refund
Função: Registrar estorno/reversão de pagamento (se implementado).


9) Financeiro

Endpoint: GET /finance/orders
Função: Listar comandas pagas em um intervalo, para alimentar tabela e cards do Financeiro.
Query:
  from: string
  to: string
  clientId?: string
  collaboratorId?: string
Saída:
  Lista de Order (apenas status = 'paid')

Endpoint: GET /finance/summary
Função: Retornar resumo numérico para os cards do Financeiro.
Query:
  from: string
  to: string
Saída (exemplo):
  totalRevenue: number   (soma de finalValue das orders pagas)
  totalCommission: number
  estimatedProfit: number

Endpoint: GET /finance/chart
Função: Retornar dados agregados para o gráfico (diário, semanal, mensal ou anual).
Query:
  from: string
  to: string
  resolution: 'day' | 'week' | 'month' | 'year'
Saída:
  Lista de pontos com nome (rótulo) e valores numéricos de faturamento/comissão

Endpoint: GET /finance/commissions
Função: Listar registros de comissão por colaborador e período.
Query:
  from: string
  to: string
  collaboratorId?: string
  paid?: boolean
Saída:
  Lista de CommissionRecord


10) Auditoria

Endpoint: GET /audit-logs
Função: Listar logs de auditoria (tela de Auditoria).
Query opcional:
  from?: string
  to?: string
  userId?: string
  tableName?: string
  action?: 'INSERT' | 'UPDATE' | 'DELETE'
Saída:
  Lista de AuditLog

Endpoint: GET /audit-logs/:id
Função: Detalhes de um log específico.
Saída:
  AuditLog


11) Notificações

Endpoint: GET /notifications
Função: Listar notificações do usuário logado (tela de Notificações, badge no menu).
Query opcional:
  unreadOnly?: boolean
Saída:
  Lista de Notification

Endpoint: PATCH /notifications/:id/read
Função: Marcar notificação como lida ou não lida.
Entrada:
  read: boolean

Endpoint: POST /notifications
Função: Criar notificação (por ações automáticas do sistema ou administração).
Entrada:
  Campos de Notification, exceto id e createdAt
Saída:
  Notification criada


12) Configurações / Aparência

Endpoint: GET /settings/appearance
Função: Obter configurações de aparência do salão (nome exibido, tema padrão etc.).
Saída (exemplo):
  platformName: string
  theme: 'light' | 'dark'

Endpoint: PUT /settings/appearance
Função: Atualizar configurações de aparência.
Entrada:
  platformName?: string
  theme?: 'light' | 'dark'


13) Totem (autoatendimento)

Endpoint: GET /totem/services
Função: Listar serviços disponíveis no totem (pode ser um subconjunto de /services).
Saída:
  Lista de Service

Endpoint: POST /totem/checkin
Função: Registrar um novo atendimento vindo do totem.
Entrada (exemplo):
  clientId?: string
  phone?: string
  name?: string
  serviceIds: string[]
Saída:
  appointment: Appointment
  (opcional) order: Order


Observação final:
Os endpoints acima cobrem o que o front atual precisa: login, controle de acesso por papel, agenda, clientes, comandas, serviços, produtos, financeiro, auditoria e notificações. À medida que o backend evoluir, é possível especializar respostas ou adicionar endpoints específicos para dashboards, mantendo estes como base de contrato.
